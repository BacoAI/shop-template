# 小型訂購網站 — 模板

**看完這份你會知道：** 這個網站能做什麼、怎麼在你自己的帳號架起來（約 15 分鐘）、商品要怎麼換成你自己的，以及哪幾段程式不能亂動。

這是一個實際上線營運過的甜點訂購網站，範例商品是「銅鑼燒」。適合**小量手作、多種商品、宅配、匯款收款**的小店。

---

## 一、它能做什麼

**看完這節你會知道：** 客人看到什麼、店主看到什麼。

**前台（客人）**

| 頁面 | 客人在這裡做什麼 |
|---|---|
| 首頁 | 看商品列表（縮圖、名稱、副標、價格）；暫停接單時會看到公告 |
| 商品頁 | 看多張照片、介紹文、配送方式、產品說明；選加購品、選數量、加入購物車 |
| 購物車 | 選出貨日、填寄件人與收件人、看運費試算、填匯款末五碼、送出訂單 |
| 完成頁 | 訂單編號、匯款銀行與帳號、應付金額、訂購明細 |

購物車有三個比較用心的地方：

- **出貨日曆只亮「全部商品都有貨」的日子** —— 不會讓客人選了才發現有一項出不了
- **冷熱不能混寄會直接擋下來** —— 判定衝突時會把下面的表單收起來，並告訴客人要分兩筆下
- **免運進度提示** —— 差多少會直接講「再買 N 元就免運」

**後台（店主，網址 `/admin`，帳號密碼登入）**

| 區塊 | 可以做什麼 |
|---|---|
| 商品設定 | 商品的新增／編輯／上下架、多張照片（上傳前自動壓縮）、價格、每單購買上限、首頁排序、產品說明、配送方式複選並指定優先、可加購品項、**每個商品各自的可出貨日曆與數量** |
| 訂單系統 | 多條件篩選、關鍵字搜尋、點欄位排序、自選顯示欄位、批次改狀態、CSV 匯出（Excel 開中文不亂碼）、單筆編輯、**改過的每一版都留著可以還原（每筆留 20 版）**、垃圾桶 |
| 網站編輯 | 營業開關（暫停接單會顯示公告並停止下單）、網站文字、匯款資訊、完成頁文案、首頁大圖，改完有即時預覽 |
| 運費管理 | 常溫／冷藏／冷凍三種各自設運費、免運門檻、要不要提供 |
| 系統管理 | 改自己的密碼、新增／刪除後台帳號、切換權限（一般／完整） |

改完按儲存，前台重整就會變 —— **不用重新部署**。

**幾個重要的保證：**

- **不會超賣。** 多人同時搶最後幾份，也只有剛好的人會成功。而且是「整車都扣得到才算數」，有一項扣不到就全部退回，不會扣一半。
- **改訂單會連動庫存。** 後台改數量、作廢、還原舊版本，賣出數量都會跟著對上。
- **後台一定留得住。** 刪帳號或降權時，系統會擋下「最後一個完整權限帳號」，不會發生沒人進得去的狀況。

**選配：** 有人下單時寄一封通知信給你（用 Resend）。不設定也能完整運作，訂單照樣成立。

## 二、技術組成

**看完這節你會知道：** 需要會什麼、不需要會什麼。

| 項目 | 用什麼 |
|---|---|
| 主機 | Cloudflare Workers（免費額度就夠小店用） |
| 資料庫 | Cloudflare D1（SQLite） |
| 照片 | Cloudflare KV（不用綁信用卡，免費 1GB、單檔 25MB） |
| 前端 | 純 HTML ＋ 原生 JavaScript，**沒有框架、沒有打包步驟** |
| 通知信 | Resend（選配，不設就不寄） |
| 部署工具 | Wrangler（Cloudflare 官方指令工具） |

改 HTML 存檔就是最終結果，不用 build（編譯）。

## 三、檔案地圖

```
├── src/                     ← 後端，六個檔各管一塊
│   ├── worker.js            ← 路由總管：哪個網址交給誰，以及把後台設定填進前台頁面
│   ├── lib.js               ← 共用工具：回應格式、時間、密碼雜湊、文案小語法
│   ├── shop.js              ← 前台 API：看商品、算錢、擋超賣、下單
│   ├── admin.js             ← 後台 API：登入、商品、日曆、加購、設定、運費、帳號
│   ├── orders.js            ← 後台訂單：篩選、匯出、編輯、版本回溯、垃圾桶
│   └── mail.js              ← 選配的下單通知信（Resend）
├── public/                  ← 前端，改完存檔就是成品
│   ├── index.html           ← 首頁
│   ├── product.html         ← 商品介紹頁
│   ├── cart.html            ← 購物車＋結帳
│   ├── done.html            ← 下單完成頁
│   ├── app.js               ← 前台共用：購物車（存瀏覽器）、API 呼叫、提示訊息
│   ├── style.css            ← 前台樣式
│   ├── admin.html           ← 後台畫面
│   ├── admin-app.js         ← 後台邏輯
│   ├── admin.css            ← 後台樣式
│   ├── twzip.js             ← 台灣本島郵遞區號（已排除離島）
│   └── dorayaki.jpg         ← 預設照片（沒上傳照片時顯示這張）
├── migrations/              ← 資料表定義（十張表），第一次部署時自動建
├── wrangler.toml            ← 網站設定（名稱、資料庫、照片倉庫）
├── package.json
├── .dev.vars.example        ← 本機測試用的環境變數範本
└── tests/                   ← 後端自動測試（52 項）
```

**前台的文字怎麼來的？** HTML 裡寫的是預設值，Worker 送出頁面前會把後台設定填進去（靠 `data-s="..."` 這些記號定位）。所以客人打開就是完成品，不會先看到範例文字再跳一下。改文案只要動後台，不用碰 HTML。

**要改後台功能時，`admin.html`（畫面）、`admin-app.js`（前端邏輯）和 `admin.js`（API）通常要一起改。**

## 四、架起來

**看完這節你會有：** 一個屬於你自己、可以真的收單的網站。

有兩條路，選一條就好。

### 路線 A：按一顆按鈕（最快，不用裝任何東西）

點這顆按鈕，用你的 Cloudflare 帳號登入，剩下的它會自己做完：

[![Deploy to Cloudflare](https://deploy.workers.cloudflare.com/button)](https://deploy.workers.cloudflare.com/?url=https://github.com/BacoAI/shop-template)

它會幫你：複製一份程式碼到你自己的 GitHub、開一個資料庫、開一個照片倉庫、建好資料表、部署上線。

需要：一個 Cloudflare 免費帳號、一個 GitHub 免費帳號。**不用裝 Node.js、不用打指令。**

### 路線 B：自己動手（想看懂每一步，或想先在自己電腦上改）

需要：Node.js 18 以上、一個 Cloudflare 免費帳號。

```bash
npm install
npx wrangler login    # 開瀏覽器登入你的 Cloudflare
npm run deploy        # 建資料庫、建資料表、上線，一次做完
```

第一次跑 `npm run deploy` 時，Cloudflare 會自動幫你建好資料庫和照片倉庫 —— 你不用先去開、也不用貼任何編號。

> ⚠ `wrangler.toml` 裡的資料庫和照片倉庫**沒有填編號，那是刻意的**。填空著它才會幫你開新的；填了別人的編號，你的訂單會寫進別人的資料庫。

### 兩條路都一樣：上線之後要做的事

- 前台 = 它給你的網址
- 後台 = 網址後面加 `/admin`

**第一次登入用 `admin` / `admin`。** 登進去系統會馬上要你設定自己的帳號名和密碼（帳號名和密碼**一起換掉**，換完 `admin` 這個帳號就不存在了）。

接著進後台做三件事就能開始收單：

1. **網站編輯** → 填匯款銀行與帳號
2. **運費管理** → 設定各溫層的運費與免運門檻
3. **商品設定** → 建商品，並在日曆上點出「哪幾天可以出貨、各能出幾份」

⚠ 第 3 步的日曆不設，客人在購物車會**選不到任何日期**，等於下不了單。

### 想改網站名稱

改 `wrangler.toml` 第一行 `name`。**不改也沒關係** —— 網址是「名稱 + 你的 Cloudflare 帳號名 + workers.dev」三段拼起來的，中間那段自動就是你自己的，不會跟別人撞。

### 選配：下單通知信

```bash
npx wrangler secret put RESEND_API_KEY   # 到 resend.com 申請，免費額度夠小店用
npx wrangler secret put MAIL_FROM        # 選填：你驗證過的寄件地址
```

沒設定就不寄信，**訂單照樣成立**，寄信失敗也不會擋下單。

### 本機測試（不動到線上資料）

```bash
cp .dev.vars.example .dev.vars
npm run db:init:local
npm run dev                       # 開 http://localhost:8787
```

本機資料庫和線上是分開的，怎麼測都不會影響真實訂單。

## 五、換成你的商品：要改哪裡

**看完這節你會知道：** 哪些東西在後台改、哪些要改程式檔。

**幾乎全部都在後台改，不用碰程式。** 這是這一版跟舊版最大的差別 —— 舊版換商品要改 HTML，現在進 `/admin` 就好。

| 在後台哪裡 | 可以改什麼 |
|---|---|
| 商品設定 | 商品名、副標、介紹文、照片、價格、每單上限、首頁排序、產品說明、配送方式、加購品、可出貨日曆 |
| 網站編輯 | 大標題、副標題、首頁商品區標題、頁尾、購物車補充說明、匯款資訊、匯款期限、完成頁文案、首頁大圖 |
| 運費管理 | 三種溫層各自的運費、免運門檻、要不要提供 |
| 系統管理 | 後台帳號與密碼 |

**文案的兩個小技巧：**

- `*星號之間的字*` 會變粗體
- 打 `{匯款期限}` 會自動換成你在「匯款期限」那格填的字，同一個日期不用改兩個地方

**產品說明的寫法：** 一行一段，用全形直線 `｜` 分隔標題和內容。例如：

```
保存方式｜冷藏 3 天，冷凍可放 2 週
過敏原｜含小麥、蛋、奶
```

**還是要改檔案的：**

| 想改的 | 檔案 | 位置 |
|---|---|---|
| 配色 | `public/style.css`、`public/admin.css` | 最上方 `:root{ ... }` 的色碼 |
| 瀏覽器分頁標題 | `public/*.html` | 各頁的 `<title>` |

改完跑 `npm run deploy` 就更新上線。

## 七、動了會出事的地方

**看完這節你會知道：** 改版時哪幾段要特別小心。這些警告在程式碼註解裡也都寫了一份。

1. **算錢只能在後端算。**
   `shop.js` 的 `calcAmount()` 是全站唯一算錢的地方，寫進訂單的金額一律由它決定。前台顯示的都只是給客人看的預估 —— 把運費交給前端算，等於讓人改個網頁就免運。

2. **擋超賣不要改成「先讀再寫」，而且要全部扣得到才算數。**
   `shop.js` 的 `takeStock()` 用有條件的 UPDATE 扣庫存，有一項扣不到就把整車已扣的退回去。D1 沒有交易可以 rollback，這個補償邏輯是自己寫的 —— 改成先 SELECT 再 UPDATE，多人同時下單就會超賣。

3. **下單中途失敗一定要收乾淨。**
   庫存要還回去、已經寫進去的半筆訂單要刪掉。不然會憑空少庫存，或留下沒人認領的孤兒訂單。

4. **改訂單一定要連動庫存。**
   `orders.js` 裡改數量、作廢、回到舊版本這三件事都會影響「已賣出的數量」。調整失敗要整筆拒絕，不能留半套。

5. **可出貨數量不能設得比已經賣掉的少。**
   `admin.js` 會擋下來。硬改的話，那些已經成立的訂單就沒貨可出。

6. **後台一定要留一個完整權限帳號。**
   刪帳號、降權限時 `admin.js` 都會擋。拿掉這道防線，有機會把自己鎖在系統管理區外面。

7. **HTML 裡的 `data-s="..."` 記號不要亂刪。**
   那是 Worker 用來認「這裡要填後台設定」的位置，刪掉那一項就變回寫死的預設字。

8. **`wrangler.toml` 的 `run_worker_first = true` 不要拿掉。**
   拿掉之後頁面會被當成一般靜態檔直接送出、跳過 Worker，後台設的文案就填不進去 —— 而且不會報錯，只是前台永遠顯示預設文字。

9. **`/cart` 和 `/cart.html` 兩種寫法都要處理。**
   `worker.js` 兩種都收。只處理一種的話，客人被 Cloudflare 導到另一種網址時，會看到沒填字的原始頁面。

10. **版本紀錄只留 20 版是刻意的。**
    每次改訂單都存一份快照，不設上限資料庫會越養越肥。

11. **金鑰不要寫進程式碼或資料庫。**
    一律用 `wrangler secret put`。

12. **已經上線有真訂單後，不要 DROP 或清空資料表。**
    要加欄位用 `ALTER TABLE ... ADD COLUMN`（只加不刪）。

13. **`.dev.vars`、`.wrangler/`、`node_modules/` 不要傳給別人或放上 GitHub。**
    `.wrangler/` 裡有本機測試資料庫，可能有訂單個資。`.gitignore` 已經幫你排除。

## 八、已知限制

- **沒有接線上金流。** 收款是 ATM／銀行匯款，客人回填末五碼，店家在後台人工核對後改「已付款」。
- **配色不能在後台改**，要動 `style.css` 的色碼（見第五節）。這是刻意的決定，不是還沒做。
- **購物車不跨裝置。** 存在瀏覽器裡，沒有會員系統 —— 換一台電腦或清掉瀏覽器資料，購物車就空了。
- **完成頁只服務「剛下單的那一次」。** 重新整理或直接開那個網址會顯示「沒有可以顯示的訂單」，沒有查詢舊訂單的功能。
- **通知信要自己申請 Resend**，而且只通知店家；「確認收款」的信要店主自己寄，網站不會自動寄。
- **冷熱不能混寄時是擋下來、不是自動拆單。** 客人要自己分兩筆下。
- **加購品的庫存是總量制**，不分日期。
- **CSV 單次最多匯出 5000 筆。**
- 本模板用 wrangler 4.x。`run_worker_first` 目前填 `true`（所有請求都先進 Worker）。想省一點請求數的話可以改成 `["/"]`，讓只有需要填字的頁面繞 Worker —— 但改了要自己測過四個前台頁面都還正常。
